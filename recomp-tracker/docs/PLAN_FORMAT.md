# Plan file format

A plan is one JSON file, `schema: "recomp-tracker-plan/1"`. Import it in the app
(*Import my plan file*) or check it first with
`node tools/validate-plan.mjs my.plan.json`.

A working, fictitious example is generated by `js/data/example-plan.js`
(try it in the app, or run `node -e "import('./js/data/example-plan.js').then(m=>console.log(JSON.stringify(m.buildExamplePlan(),null,1)))"`).

**Keep real plan files out of git** (`*.plan.json` is ignored).

## Top level

```jsonc
{
  "schema": "recomp-tracker-plan/1",
  "name": "My plan",                    // shown in the app
  "source": "optional note",
  "profile": { "name": "…", "sex": "M", "age": 30, "heightCm": 178, "weightKg": 78, "bfPct": 18 },
  "phase": "recomp",                    // recomp | cut | bulk | maintain (drives the review)
  "slots":    { "breakfast": { "label": "Breakfast" }, … },
  "dayTypes": { … },                    // required: rest, lift, cardio, lift_cardio
  "foods":    [ … ],                    // optional: foods the menus use, or overrides of built-ins
  "menus":    { "A": { "label": "Menu A", "days": { … } } },   // optional
  "program":  { … },                    // optional training program
  "supplements": [ … ],                 // optional
  "cardio":   { "weeklyKcalGoal": 0, "met": 9.8 },
  "hydration": { "goalMl": 3000 }
}
```

`menus`, `program` and `supplements` are optional. A plan with only `dayTypes`
works: you log foods by hand and the targets guide you.

Identifiers (food, menu, slot, supplement, exercise, program-day and edition ids) must
use letters, numbers, `-`, `_` and `.` only, at most 64 characters.

## dayTypes

All four are required. Energy is calculated from the macros, so only P/C/F are given.

```json
"dayTypes": {
  "rest":        { "target": { "p": 160, "c": 230, "f": 45 }, "tdee": 1960, "slots": ["breakfast", "lunch", "dinner"] },
  "lift":        { "target": { "p": 160, "c": 300, "f": 50 }, "tdee": 2300, "slots": ["pre", "post", "lunch", "dinner"] },
  "cardio":      { "target": { "p": 160, "c": 295, "f": 50 }, "tdee": 2290, "slots": ["breakfast", "lunch", "dinner"] },
  "lift_cardio": { "target": { "p": 160, "c": 365, "f": 59 }, "tdee": 2630, "slots": ["pre", "post", "lunch", "dinner"] }
}
```

`tdee` is optional. When present, the review uses it as the floor when it suggests
taking carbs off training days.

## foods

Per 100 g (or 100 ml), or per serving. A plan's foods override built-in foods with the
same id, which lets a plan pin food values to exactly the numbers a coach used.

```json
{ "id": "chicken-tenderloin-raw", "name": "Chicken tenderloin, raw", "th": "สันในไก่ ดิบ",
  "cat": "protein", "p": 22.6, "c": 0, "f": 1.7, "cr": 0.77 }
```

- `cat`: `protein`, `carb`, `fat`, `fruit`, `veg`, `dairy`, `drink`, `dish`, `other`.
  Swaps match protein foods on protein, carb foods on carbs, fats on fat.
- `unit`: `g` (default), `ml`, or `serving` (then macros are per 1 serving).
- `cr`: cooked weight ÷ raw weight, display only ("≈ 154 g cooked").
- `a`: grams of alcohol per 100 ml (7 kcal/g).

## menus

```json
"menus": { "A": { "label": "Menu A", "days": {
  "lift": {
    "pre":  [ { "food": "whey-concentrate", "q": 20 }, { "food": "bread-white", "q": 110 } ],
    "lunch": [ … ]
  }
} } }
```

`q` is the weighed amount in the food's unit. The validator warns if a menu is more than
5% away from its day target.

## program

```jsonc
"program": {
  "name": "Pull / Push / Leg / Rest",
  "cycle": ["pull", "push", "leg", "rest1"],        // repeats; the app tracks "today is day N"
  "days": { "pull": { "label": "Pull", "dayType": "lift" }, "rest1": { "label": "Rest", "dayType": "rest" } },
  "editions": {                                    // e.g. gym and home versions
    "gym": { "label": "Gym", "days": {
      "pull": [
        { "id": "pull-lat-pulldown", "name": "Lat pulldown", "note": "form cue",
          "rest": 90, "restAfter": 180,
          "sets": [ ["feel", 20], ["warm", 12], ["w15", 12], ["w1", 12], ["fail", 12], ["drop", 12] ] }
      ]
    } }
  }
}
```

- A set is `[type, targetReps]`; `targetReps` may be `null` (log your own reps).
- Set types: `feel`, `warm`, `w2` (2 reps in reserve), `w15`, `w1`, `w05`, `work`,
  `fail`, `drop`. Only `w2`…`drop` count toward volume.
- `rest`: seconds between sets. After a set that is followed by a `drop`, the timer
  always uses 10 s. `restAfter`: seconds after the last set, before the next exercise
  (use `0` for none).
- Give an exercise a different `id` per program day if its sets differ between days, so
  volume comparisons stay fair.

## supplements

```json
{ "id": "creatine", "name": "Creatine monohydrate", "dose": "5 g",
  "timing": "post", "base": true, "note": "every day" }
```

`timing`: `morning`, `midday`, `pre`, `intra`, `post`, `sleep`. `base: true` means it is
ticked by default in *My supplements*.
